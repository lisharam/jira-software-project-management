STUDENT MANAGEMENT SYSTEM — JIRA-STYLE DEMONSTRATION WEBSITE

HOW TO RUN
1. Extract this ZIP file.
2. Open index.html in a modern browser (Chrome recommended).
3. No installation or server is required for the demo.

FEATURES
- Separate Overview and Project board screens
- Dashboard summary, workflow progress bars and recently added issues
- Kanban-style board with three workflow columns
- Create, edit and delete Task, Story and Bug issues
- Set descriptions, priority, status, assignee, due date and sprint
- Change task status directly on a card
- Add comments to issues
- Search issues and filter by priority and issue type
- Manage team member profiles and assignments
- Plan, start and complete sprints
- Reports for completion, overdue issues, priorities and team workload
- Smart insights for rules-based due-date risk, stuck blockers and workload balancing
- Split issues into editable subtasks
- What-if sprint estimates for extra scope and delivery delays
- Optional daily workload/stress check-ins and a self-reported eco progress score
- Switch between light and dark themes
- Create and sign in to a local demo profile
- Assignment opens a prefilled email draft for the selected team member
- Export project issues, assignee email addresses and report data as CSV
- Keyboard-friendly issue dialog and visible save-error notifications
- Reset demo data
- Saves changes in the current browser using localStorage
- Responsive layout for laptop and mobile

DEMO PROJECT
Student Management System
Example issues are included to support a class demonstration.

NOTE
This is a standalone Jira-inspired educational demo, not an Atlassian Jira export or integration. Tasks, team members, comments, sprints, and preferences are stored in the current browser and are not synced to a server.

AUTHENTICATION LIMITATION
The sign-in and signup controls create/select a local demo profile only. They do not use passwords, verify identity, or provide secure authentication. Do not enter sensitive information. Real multi-user accounts require a backend authentication service.

EMAIL LIMITATION
Assigning an issue opens a prefilled message in the device's configured mail app for members with a real email address. Example addresses ending in @example.com are intentionally not mailed. The member's email address, issue summary, description, due date, and sprint are included where available. The user must review and send the draft; this static browser demo cannot deliver email automatically. Automatic delivery requires a backend mail service.

INSIGHTS LIMITATION
Risk levels, blocker warnings, workload suggestions, and sprint simulations use transparent local rules and estimates. They are not machine-learning predictions and are not delivery guarantees. Team pulse responses and sustainability actions are self-reported and stored locally.
